# Rank AI — Content Writer (System 2)

Skill 2 in the Rank AI SEO operations layer. Wraps `rank-ai/scripts/content_writer.py` which orchestrates the full one-post-per-run pipeline: Anthropic → Gemini image → WebP → R2 → markdown → commit → sync-deploy.

Source of truth for content quality: `rank-ai/templates/restoration/prompts/content-writer.md` (the prompt) + `rank-ai/clients/{slug}/image-style-guide.md` (the visual contract).

## When to invoke

The user says any of:

- "write the next post for {client}" / "next blog post"
- "publish the next item in the queue"
- "rank-ai-content-writer" / "system 2" / "run content writer"
- "what's next to publish for {client}"

Also invoke automatically (in headless cron mode) on the schedule the master scheduler defines (typically Monday + Thursday 9am once Skill 4 + scheduler ship).

## Pre-flight

1. **Determine the client slug.** Ask via `AskUserQuestion` if not provided. Available clients = `rank-ai/clients/*.json` (exclude subdirectories).
2. **Validate prerequisites:**
   - Client record `status: "active"` and `plan_status: "planned"` and `build_status` is `pushed_main` or `cut_over` (we don't write blog posts for sites that aren't deployed yet)
   - `clients/{slug}/content-queue.json` exists AND has at least 1 item with `status: "queued"` (if not, suggest running `rank-ai-keyword-researcher` first)
   - `clients/{slug}/image-style-guide.md` exists (auto-generated by `rank-ai-plan-site`)
3. **Source the env:** `set -a; . rank-ai/.env; set +a` for `ANTHROPIC_API_KEY`, `GOOGLE_AI_API_KEY`, `CLOUDFLARE_R2_API_TOKEN`, `GITHUB_PERSONAL_ACCESS_TOKEN`.

## Run the writer

Default — push to staging for review:

```bash
cd ~/Desktop/mywebsitecode/rank-ai
set -a; . .env; set +a
python3 scripts/content_writer.py next-post --slug {slug} --branch staging
```

For production-ready posts (when the user trusts the pipeline):

```bash
python3 scripts/content_writer.py next-post --slug {slug} --branch main
```

The script:
1. Pops the oldest priority-1 queued item from `clients/{slug}/content-queue.json`
2. Builds the Anthropic prompt by merging the source-of-truth content-writer.md + client context + image-style-guide
3. Calls Claude Sonnet 4.6 — gets back `{title, meta_description, body_markdown, faq, image_prompt, internal_link_suggestions}`
4. Calls Nano Banana Pro with the `image_prompt` → PNG bytes
5. Converts PNG → WebP via `scripts/image_utils.py` (quality 90)
6. Uploads to R2 at `images.{domain}/blog/{YYYY}/{MM}/{post-slug}/hero.webp`
7. Writes markdown at `sites/{slug}/src/content/blog/{post-slug}.md` with full frontmatter matching the content collection schema. The `youtube_id` field in frontmatter is left blank (`youtube_id: ""`) at write time — System 5 (`video_maker.py`) fills it in post-publish once a video is created. When `youtube_id` is present, the blog page automatically emits a `VideoObject` JSON-LD schema block alongside `BlogPosting` — no extra code needed.
8. Updates the queue item: `status: written`, `written_at`, `post_url`
9. Commits the monorepo (single commit per post)
10. Runs `build_site.py sync-deploy --slug {slug} --branch {target}` to push the subtree to the per-client GitHub repo
11. Cloudflare Pages auto-builds. Post is live in ~60-90s.

Surface stdout verbatim. The script prints a clear 5-step progress (`[1/5] Generating body...` etc.).

## Flags worth knowing

- `--branch staging` (default) — push to staging branch for preview review
- `--branch main` — push directly to production (use when trusted)
- `--flash` — use Nano Banana Flash instead of Pro (cheaper, lower quality — use only when budget-tight)
- `--skip-image` — skip image generation entirely (leaves `hero: ""` in frontmatter — only for testing the text pipeline)
- `--no-image-fallback` — if image gen fails, abort instead of falling back to brand hero
- `--no-deploy` — write the post locally but don't commit or sync-deploy (useful for content review)
- `--dry-run` — show what the next queue item is without writing
- Note: `youtube_id` is intentionally left empty in the written post. System 5 (`rank-ai-video-maker`) runs separately after the post is live and patches the frontmatter with the YouTube video ID, triggering a re-deploy that adds the embed + VideoObject schema.

## CI / dependency requirements

- `requirements.txt` **must contain `Pillow>=10.0.0`** — `image_utils.py` calls `PIL.Image` for PNG→WebP conversion. If Pillow is missing, the script exits with `rc=1` immediately on import before any API call is made. Symptoms: every S2 CI run shows `FAILED with rc=1` in under 200ms.
- `.gitignore` **must include `.DS_Store`** — macOS creates this file at repo root; it causes `sync-deploy` to report "Working tree has uncommitted changes" on every local run.
- `content_writer.py commit_and_sync` calls `sync-deploy --allow-dirty` — `build_site.py sync-deploy` updates `clients/{slug}.json` with a `last_pushed_main_at` timestamp on success, leaving the file dirty for the next invocation. `--allow-dirty` prevents this from blocking subsequent runs.
- `git pull --rebase --autostash` — `commit_and_sync` uses `--autostash` so locally-dirty files (untracked or unstaged) are stashed before the rebase and restored after.

## Error handling

- **Empty queue** → tell the user, suggest `rank-ai-keyword-researcher`
- **Anthropic rate limit / 5xx** → built-in retry-with-backoff handles transient. Sustained failure surfaces verbatim.
- **Gemini image failure** → defaults to using the brand hero (`/brand/hero.webp`) unless `--no-image-fallback`
- **R2 upload failure** → surface, do NOT commit (we don't want a post with a dead image)
- **sync-deploy failure** → post markdown is on disk + queue updated; user can run sync-deploy manually after fixing

## Hard rules (also enforced by the prompt)

- One post per invocation. No batching.
- Never write outside `sites/{slug}/src/content/blog/` and `clients/{slug}/content-queue.json`.
- Never re-write an item with `status: written`.
- Never push to `main` without the user's explicit choice (staging is default).
- Never fabricate testimonials, statistics, or customer names.
- For sensitive-content services (biohazard / crime / hoarding / meth lab), the prompt enforces clinical tone + no graphic detail.

## What this skill does NOT do (out of scope)

- Keyword research / topic discovery — that's `rank-ai-keyword-researcher` (System 1)
- Onsite Lighthouse audits — that's `rank-ai-onsite-audit` (System 3)
- Content refresh / decay detection — that's `rank-ai-refresh-recommender` (System 4)
- Cut-over to apex domain — that's `rank-ai-build-site cut-over`
- Cross-client batch operations — that's the master scheduler
- Manual content edits — for one-off rewrites, edit the markdown directly + sync-deploy
- Video creation — that's `rank-ai-video-maker` (System 5), which generates a YouTube video for the post and patches `youtube_id` into the frontmatter
