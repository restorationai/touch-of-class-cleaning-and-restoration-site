**The campaign works; the conversion tracking is broken.** Twilio subaccount logs for the tracking number **253-338-5162** show ~10 CONNECTED calls over 6/24–6/28 (11–159s, several WA area codes), all forwarded to the real line 206-883-0333. Since ONLY the noindex ad LPs use 253-338-5162 (the main site uses the real NAP number), **every one of those calls is an ads-LP lead.** Yet Google Ads logged **0** "Calls from ads"/phone-lead conversions over the same window (last was 6/23) — only GBP "Local actions" registered.

**Root cause:** LP tel-taps dial the Twilio number directly, so Google never sees the call — the only thing that can count it is the **gtag click-to-call conversion `AW-16824131335`**, which is firing/counting as ~0. So the dashboard's "0 conversions" is a tracking artifact, not dead traffic.

**Why it matters:** We halved the budget TWICE (now $137.50/day ceiling) believing the campaign produced nothing. That was based on the broken metric. **Do not keep cutting on the 0-conv illusion.**

**ROOT CAUSE FOUND + FIXED + DEPLOYED 2026-07-03:** Astro `define:vars` wraps every inline script in its own IIFE, so the loader's `function gtag()` never became `window.gtag`, and the tel-click handler (separate IIFE) had `typeof gtag !== 'undefined'` ALWAYS false — the conversion never fired once, on any site, since launch. The Google Ads side was verified correct (action `Lead · Phone Call` id 7647450951 ENABLED/primary, label matches brand.ts). Fix: `window.gtag = gtag;` in the loader + `typeof window.gtag === 'function'` in the handler + `transport_type: 'beacon'`.
